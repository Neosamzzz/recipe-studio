# 配方工作室 · Recipe Studio

用于 Minecraft 材料与配方规划的本地可视化编辑器。将 Item、界面贴图和槽位放到工作区，自由组合合成面板、编排配方，并通过本地 HTTP API 与 AI 协作修改工程。

前端使用原生 HTML、CSS 和 JavaScript，服务端使用 Python 标准库，无需安装项目依赖或构建前端。

[快速开始](#快速开始) · [编辑配方](#编辑配方) · [操作速查](#操作速查) · [动态物品图标](#动态物品图标) · [本地-api](#本地-api) · [开发与验证](#开发与验证)

## 功能

- **独立资源库**：Item 分类目录、文件素材目录和合成面板模板分别管理；最近使用的 Item 可直接拖取。
- **自由工作区**：支持默认九宫格和自定义贴图面板，槽位可自由布局、吸附对齐，底图可调整大小。
- **物品拿取**：Item 图标与数量跟随鼠标，支持放入槽位、交换物品和独立摆放。
- **配方管理**：一个 Item 可有多条配方，支持预览、切换、删除，以及整张添加到工作区。
- **工程编辑**：支持 CAD 方向框选、整组移动、组合与解耦，以及最多 100 步撤销／重做。
- **本地保存与 AI 接入**：自动保存工程，支持 JSON 导入导出和带版本校验的 HTTP API。

> [!NOTE]
> 这是配方设计与梳理工具。初始内容为示例 Item；工具不会修改 Minecraft 文件、注册游戏物品或直接导出模组配方。

## 快速开始

需要 **Python 3** 和支持现代 JavaScript 的桌面浏览器。

| 平台 | 启动方式 |
| --- | --- |
| Windows | 双击 `启动.bat`，自动检测 `py -3`、`python` 或 `python3` |
| macOS | 双击 `启动.command`，使用 `python3` |
| 命令行 | 在项目目录运行 `python3 server.py --open`；Windows 可使用 `py -3 server.py --open` |

启动后自动打开 <http://127.0.0.1:8766/>。保持服务窗口打开，在终端按 `Ctrl+C` 或关闭服务窗口即可停止。

可通过命令行指定端口和独立工程文件：

```sh
python3 server.py --port 8767 --state .local/another-project.json --open
```

Windows 提示找不到 Python 时，请先安装 Python 3 并启用 **Add Python to PATH**。默认端口被占用时，可停止原服务，或使用 `--port` 指定其他端口。

## 界面与对象

| 区域 | 用途 |
| --- | --- |
| 左上：Item 库 | 按可展开的分类目录管理物品，搜索、创建 Item、绑定图标；目录下方显示最近拖出的物品 |
| 左中：文件与素材 | 浏览导入的图片及文件夹层级，将贴图拖入工作区 |
| 左下：合成面板模板 | 存放默认九宫格、自定义组合模板与已保存的自定义合成面板 |
| 中间：工作区 | 摆放图片、槽位和 Item，调整布局并组合 |
| 右上：属性 | 查看 Item 信息，或编辑选中对象的位置、尺寸、槽位用途及数量 |
| 右下：配方查看 | 查看当前 Item 的合成面板与产出，管理多条配方 |

**Item** 是物品定义，工作区中的物品引用其 ID。**素材** 是用于布局的图片。**模板** 保存可复用的面板布局，保存时清空槽位中的 Item。**配方** 保存具体的投入、产出和数量。

任意位置点击 Item，包括目录、最近栏、工作区和配方预览，都会在右侧显示该物品的属性与配方。

## 编辑配方

### 使用默认九宫格

1. 点击工具栏的 **＋ 九宫格**，添加一个完整面板。
2. 从 Item 库拖动物品到槽位；需要时在属性中调整数量。
3. 右键槽位切换 **设置为输入槽位／设置为输出槽位**。菜单只显示可切换到的另一种用途。
4. 在放有产出 Item 的输出槽位上右键，选择 **保存配方…**，填写名称并保存。
5. 点击产出 Item，在右下查看配方；多条配方使用 **前一个／下一个** 切换。

### 制作自定义面板

1. 在“文件与素材”区域右键，导入图片或本机文件夹。
2. 将底图拖入工作区，开启 **放置槽点**，在需要的位置点击添加槽位。
3. 关闭放置模式，拖动槽位吸附对齐，或在属性中输入精确的 X、Y 坐标。
4. 单独选中图片后，拖动右下角控制点或输入宽高调整大小；默认保持比例。
5. **右键拖动框选**需要的对象，再右键选择 **组合为模板／组合为配方**。只有通过右键拖动得到的框选集合会显示这两个操作。

保存模板时无需填写产出 Item。组合为配方时必须存在填入 Item 的输出槽位；缺少输出会拦截保存。存在未归位的 Item 时会提示返回调整，或确认将其保留为展示对象；展示对象不作为配方投入或产出。

### 复用与删除

右下的 **整张配方添加到工作区** 会添加一个完整组合，拖动底图可移动整组。右键底图选择 **解耦该配方** 后，可以分别编辑内部对象。组合中的 Item 仍可单独拿取。

**删除该配方** 需要弹窗确认，只删除当前配方，保留 Item、模板及工作区对象。

## 操作速查

| 操作 | 效果 |
| --- | --- |
| 左键拖动空白 | 平移工作区 |
| 滚轮 | 以鼠标位置为中心缩放，网格点间距随缩放自适应 |
| 右键从左往右拖动 | 蓝色实线框，仅选择被完整包含的对象 |
| 右键从右往左拖动 | 绿色虚线框，选择与框相交的对象 |
| 左键拖动选中底图或对象 | 移动选中集合；组合配方按整体移动和框选 |
| Shift 点击 | 增减选择 |
| 从库中拖出 Item | 复制到槽位或工作区空白处 |
| 从工作区拿取 Item | 移动；放入已占用槽位时交换物品 |
| 拿取中按 Esc，或放到工作区外 | 取消拿取，物品回到原处 |
| Delete／Backspace | 删除选中的工作区对象 |
| Ctrl+Z／⌘Z | 撤销 |
| Ctrl+Shift+Z／⌘⇧Z | 重做 |

一次完整拖动记为一步。工程内容修改和接收到的 API 修改均可撤销；平移、缩放和框选不计入历史。输入框保留文字撤销。历史仅保留在当前页面会话，最多 100 步，刷新后清空；撤销后继续编辑会清空重做记录。

## 动态物品图标

在 **Item 目录中右键物品 → 绑定图标…**，选择图片。Minecraft 动态贴图可同时选择 PNG 与同名 `.png.mcmeta`，也可先绑定 PNG 后单独选择配置文件。

支持 `frametime`、`frames` 帧顺序与单帧时长、`interpolate` 插值，以及 `width`、`height` 帧尺寸。时间按每 tick 50 ms 计算，例如：

```json
{
  "animation": {
    "frametime": 3,
    "frames": [0, 1, { "index": 2, "time": 6 }, 1],
    "interpolate": true
  }
}
```

竖向排列的正方形 PNG 帧图未附配置时，编辑器默认按顺序播放。图标和动画配置随工程保存，在目录、工作区、预览、属性、最近栏和拿取时同步显示。

## 工程保存

工程自动保存到项目目录下的 `.local/project.json`，下次启动恢复。文件包含 Item、分类、图标、素材图片、工作区、模板、配方及视图状态。

- **保存工程**：导出包含图片数据的 JSON，便于备份或转移到另一台电脑。
- **打开工程**：用导出的 JSON 恢复工程，兼容旧版本工程文件。
- 撤销／重做后的工程状态同样会自动保存，撤销历史本身不写入工程文件。

> [!TIP]
> 转移工程时使用“保存工程”导出 JSON；只复制源码不会携带被 Git 忽略的 `.local/` 本机工程数据。

## 本地 API

服务仅监听 `127.0.0.1`，页面与 API 共用同一份工程。AI 无需操控界面即可读取和修改数据。

建议依次读取 `/api/schema` 和 `/api/summary`，再查询需要修改的资源。首次启动时，先打开页面完成初始同步；此之前 `/api/project` 的 `project` 为 `null`。

| 请求 | 用途或请求体 |
| --- | --- |
| `GET /api/schema` | 接口、资源字段和校验规则 |
| `GET /api/summary` | Item 名称与 ID、配方／模板索引、对象数量，不含图片数据 |
| `GET /api/project` | 完整 `{revision, project}` |
| `PUT /api/project` | `{revision, project}`，整体替换工程 |
| `GET /api/<resource>` | 资源列表，返回 `{revision, values}` |
| `GET /api/<resource>/<key>` | 单条资源，返回 `{revision, value}` |
| `POST /api/<resource>` | `{revision, value}`，新建资源 |
| `PATCH /api/<resource>/<key>` | `{revision, changes}`，按字段更新单条资源 |
| `DELETE /api/<resource>/<key>` | `{revision}`，删除单条资源 |

资源名为 `items`、`categories`、`objects`、`recipes`、`templates`、`files`。`items` 与 `objects` 使用字符串 ID，其余资源使用从 0 开始的数组索引。新建 Item 时可附加 `category: ["加工材料", "压缩板"]` 指定目录。

例如，先读取最新 revision 和目标 Item ID，再发送改名请求：

```http
PATCH /api/items/plate-a
Content-Type: application/json

{"revision": 3, "changes": {"name": "强化面板"}}
```

将示例中的 `3` 替换为刚读取的 revision。写入成功返回新的 `revision` 和 `warnings`；版本过期返回 `409`，应重新读取并核对差异后再提交。引用断裂、无效数量或缺少有效输出的配方会被拒绝，失败不会部分写入。

图片与图标使用 `data:image/...` 内嵌数据。动态 Item 通过 `iconAnimation` 保存完整 `.mcmeta` JSON；设为 `null` 可恢复静态显示。字段定义以 `/api/schema` 为准。

页面约每秒同步一次；拖动、编辑输入框或打开弹窗时暂缓接收外部更新。页面和 API 同时修改时，会提示选择采用 API 版本或保留当前页面，避免静默覆盖。

## 开发与验证

| 文件 | 职责 |
| --- | --- |
| `index.html` | 编辑器界面、工作区交互、工程状态与同步 |
| `icon-animation.js` | Minecraft 贴图动画解析与播放计算 |
| `server.py` | 本地 HTTP 服务、资源 API、版本校验与持久化 |
| `assets/` | 内置示例合成面板贴图 |
| `tests/` | 服务端 API、编辑器逻辑和动态贴图测试 |

运行测试需要 Python 3 和 Node.js，无需安装额外测试依赖：

```sh
python3 -m unittest discover -s tests -v
node tests/test_editor.js
node tests/test_icon_animation.js
```

调试时可用 `--port` 与 `--state` 启动独立工程，避免改动正在使用的数据。
